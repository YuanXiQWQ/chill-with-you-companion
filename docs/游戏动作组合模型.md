# 游戏自己怎么组合动作

从 `AnimationType` 枚举全量导出（262 个成员，`data/anim-types.txt`）。

## 一句话

**`<Base>_<Sub>` —— 基底 + 子动作，游戏已经把组合做好了，而且是每个基底一套子动作表。**

不是层混合（L0 只有单一 state，`blends=1`），是**状态机串行切换**。我们看到她"待机中时不时喝口茶"，实际是：`BreakBase004` → `BreakBase004_DrinkTea` → 回到 `BreakBase004`。

## 三条硬规律

### ① 同一个语义，不同基底有不同实现

`DrinkTea` 出现在 **4 个基底**里：`BreakBase004` / `WorkBase001` / `WorkBase002` / `WorkBase003`。

**同一个"喝口茶"，她坐着休息、在工位、在看书时身体姿势完全不同。** 拿去交叉用就是错的。

`Thinking` 也是：`WorkBase001` / `WorkBase002` / `WorkBase003` 都有。

`Stretch` 只在 `BreakBase004`——**坐着**伸懒腰。站着的版本是 `Wild001_Motion1_StretchFllBody`，两回事。

### ② 长时间活动是 `Start` / `Loop` / `End` 三段

```
StartUseCoffeeMaker → LoopUseCoffeeMaker → EndUseCoffeeMaker
StartBreakMovie     → LoopBreakMovie     → EndBreakMovie
StartBreakReadBook  →                    → EndBreakReadBook
StartSpinning       → LoopSpinning       → EndSpinning
```

**`Loop` 是 `loop=true` 的，可以停任意长时间。** 这是游戏处理"看两小时电影"的方式——不是播一个两小时的 clip。

`Wild003` 的 `LeaveChair_*_Comeback` / `_Comeback_Loop` 同理。

### ③ 工位之间切换有专门动作

```
FromPcToBook      FromBookToPc
FromPcToReport    FromReportToPc
FromBookToReport  FromReportToBook
```

**六个方向各有一条**，不是瞬移。我们在 `WorkBase002`（敲键盘）想让她去看书，正确顺序是 `FromPcToBook` → `Base001`（或 `WorkBase002`→…），而不是直接 `ChangeAnimation("看书")`。

## 手为什么会交叉

**我们播的是固定 clip：`anim_break_tea_sub_drink`（1833 ms）。**

看它的兄弟：

```
anim_break_tea_sub_drink      1833ms  loop=false
anim_break_tea_sub_drink_loop 1167ms  loop=true
anim_break_tea_sub_drink_end  1167ms  loop=false
```

**`_sub_*` 不是独立动作，是叠加在 `base_loop` 上的片段**：它从"坐着、手放在膝盖上"的姿势出发抬杯、喝、放回。**单独播放等于凭空抬手**——基准姿势不对，手臂落到错的位置，两只手就交叉了。

而 `BreakBase004_DrinkTea` 是**游戏组合好的版本**：自带 base 上下文、自带对齐。**用它对，用 `anim_*_sub_*` 错。**

## 落地方式

**子动作名不写死，按当前基底拼。**

DLL 侧：

```cs
string baseName = CurrentBase();          // "BreakBase004"
string cand = baseName + "_" + sub;       // "BreakBase004_DrinkTea"
if (EnumExists(cand)) use(cand);
else try nativeAlt;                        // 站着的版本
else fallback to sampling;
```

服务端只下发**后缀**（`DrinkTea`），不写全名——因为全名取决于她此刻在哪。

这比"写死一个全名"抗更新得多：游戏加一个新基底，只要它带 `DrinkTea` 子动作，我们自动就能用。

### 落地时踩到的三个坑

**① 游戏端读的不是 `performance` 对象数组**

`brain.mjs` 一直在发扁平平行数组：

```js
act.slots = performance.map(c => String(c.slot))
act.ids   = performance.map(c => String(c.id))
act.ats   = performance.map(c => Number(c.at) || 0)
```

注释写得很清楚：**`JsonUtility` 对「对象数组」解析不可靠，游戏端只读这三个平行数组**。

所以 `nativeName` / `nativeSub` 写在 `performance` 里**游戏端永远收不到**。必须也进平行数组：

```js
act.nativeNames = performance.map(c => String(c.nativeName || ''))
act.nativeSubs  = performance.map(c => String(c.nativeSub || ''))
```

**② DLL 有两条解析分支，都得读**

`CueDto` 的解析先试 `performance` 对象数组，`cues.Count == 0` 才走平行数组。两条分支写法不同，改一条不够。实测第一条分支**是会进的**（`sub=[]` 就是这么来的），两条都要补 `nativeSub`。

**③ 当前基底可能真没有这个子动作**

第一次测直接翻车：

```
cue in: slot=animations id=anim_break_tea_sub_drink sub=[DrinkTea] name=[]
native sub: 枚举无 BreakBase002_DrinkTea (cur=BreakBase002)
```

她当时在 `BreakBase002`——**看书**。`BreakBase002` 的子动作只有 `NextPage` / `PreviousPage` / `Interest`，**书里没有"喝口茶"这一下**。这不是 bug，是游戏的设计：她不会一边翻页一边端杯子。

既然我们接了"让她喝水"的指令，就得**换一个有这个子动作的基底**：

```cs
private static readonly string[] SubFallbackBases = {
    "BreakBase004", "WorkBase002", "WorkBase001", "WorkBase003",
    "BreakBase001", "BreakBase002", "BreakBase003", "BreakBase006",
};
```

顺序按「最接近日常待人」排，`BreakBase004`（坐着休息）最自然。实测：

```
native sub: BreakBase002 无 DrinkTea，改用 BreakBase004_DrinkTea
native play BreakBase004_DrinkTea
native done BreakBase004_DrinkTea started=True
```

## 还没做的

- **`WorkBase001` 的 `Break` / `Break2`** 语义未确认（是"休息"还是"打断"）
- **`Wild003` 的 `LeaveChair_*` 与 `trip` 链路**未对齐
- **三段式还没用上**：`StartUseCoffeeMaker` / `LoopUseCoffeeMaker` / `EndUseCoffeeMaker` 这类
  长活动仍然走采样。它们要的是状态机切换，不是播一次动
