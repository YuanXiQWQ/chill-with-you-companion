# 口型的抗更新设计

## 一句话

**每帧那几个数的顺序，只有 `lib/lipsync.mjs` 的 `CHANNELS` 一个定义源。** 游戏端不再保留自己那份副本。

## 以前的毛病

`lib/lipsync.mjs` 写着 `CHANNELS = ['a','i','u','e','o','n']`，`PerformerPlugin.cs` 里另有一份 `MOUTH_KEYS = ["mouth_a","mouth_i","mouth_u","mouth_e","mouth_o","mouth_n"]`。

两份独立定义靠人眼保持一致。改一处忘另一处，结果是**嘴在动，但母音全错位**——不报错、不警告，看起来完全正常。

这和之前合并掉的 `SHARED` / `COMPANION_VERBS` 逐字重复是同一个病。那两处也各爆过一次静默故障（`toNative` 键碰撞、`shake` 三重失效）。

## 现在的契约

```
lib/lipsync.mjs   CHANNELS = ['a','i','u','e','o','n']      ← 唯一定义源
brain.mjs         flatMouth() 返回 { ..., mouthChannels: CHANNELS }
DLL ActDto        mouthChannels: List<string>
DLL FindFace()    按 mouthChannels 的顺序填 mouthIdx
```

服务端加通道、减通道、换顺序，游戏端跟着走，**不用改一行 C#**。

## 三个抗更新的判据

### ① 网格是谁：看有没有母音，不看叫不叫 Face

以前：

```cs
if (smr.sharedMesh.name != "Face" && smr.name != "Face") continue;   // 改网格名就断
```

现在：扫所有带足够 blendshape 的 `SkinnedMeshRenderer`，**谁能对上最多母音通道谁就是脸**。名字只在命中数并列时用来排序（优先含 `face`）。

### ② blendshape 是谁：看结尾形态，不看整串名字

以前：`low.EndsWith("mouth_a")` —— 游戏换成 `M_A` / `vowel_a` 就断。

现在：

```cs
// 结尾是那个字母，且前一个字符是分隔符
private static bool IsChannelShape(string lowName, string ch)
{
    if (lowName[lowName.Length - 1] != ch[0]) return false;
    char prev = lowName[lowName.Length - 2];
    return prev == '_' || prev == '.' || prev == '-' || prev == ' ';
}
```

命中：`mouth_a` / `Mouth_A` / `vowel_a` / `v.a` / `A`

**不命中**：`Mouth_narrow`（结尾 `w`）、`Mouth_wide`（结尾 `e`，但前一个字符是 `d`）、`Mouth_smile`

最后那条是这个判据存在的理由：天真的"以 `e` 结尾就是母音 e"会把 `Mouth_wide` 认成 `e`。

### ③ 断了要能看见

以前匹配不上只打 `LogInfo("... mouth[]")`，和"语音引擎没装自动降级"长得一模一样。

现在两条：

```
face bound: Character/Face shapes=57 hit=6/6 mouth[a=5 i=2 u=4 e=1 o=3 n=0]
mouth bind incomplete 4/6 on XXX; shapes=57 [blendShape1.Mouth_n | blendShape1.Mouth_e | ...]
```

第二条是 `LogWarning`，并且**把网格上的 blendshape 名打出来**。游戏更新换了命名，直接读日志就知道新名字，照着改一行，不用开反编译器。

## 非侵入边界

| 层面 | 做法 |
| --- | --- |
| 游戏文件 | 一个都不写 |
| mesh / 材质 / prefab | 不碰 |
| 组件方法 | 不打补丁、不 hook、不替换 |
| 游戏状态机 | 不知道我们在做任何事 |
| 运行时写入 | 只写 `Mouth_a/i/u/e/o/n` 六个通道，其余 18 个嘴部 blendshape 不碰 |
| 不写的时候 | `mouthActive == false` 立刻停手，`ClearMouth()` 归零 |

**唯一的状态侵入**是每帧覆盖那六个通道（`UpdateMouth` 在 `LateUpdate`，晚于游戏的 Animator 写入）。

## 明确不做的事

**不读 L3 Talk 层的状态来判断"游戏是不是在说话"。**

那条判断看起来聪明，实际是抗更新的反方向：它依赖层索引 `3`。游戏调一次层序，判断就静默失效，比不判断更糟。

现在的 `mouthActive` 条件已经够用——它只在我们自己播 TTS 语音时为 true，游戏播原生语音时我们不播 TTS，天然不重叠。

`mouthIdx` 按 `channels` 顺序填：`a→5, i→2, u→4, e→1, o→3, n→0`。

## 还有一个软依赖

口型数据来自 TTS 音频时长。**TTS 引擎不在时 `mouthFlat` 就是空的**（`skipTts:true`，`audioUrl:null`），嘴不动——这是设计行为，和"语音引擎不可用则降级为纯字幕"一致。

排查时先看 `data/tts.log` 有没有 `fetch failed`，再看 `mouthChannels` 有没有值：**有 channels 但 flat 为 0 = 没音频；两个都空 = 服务端没算**。
