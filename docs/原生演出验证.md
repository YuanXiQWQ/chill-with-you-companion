**不可用**：`Base001_*`（点头/害羞/思考/低头/推眼镜等 24 个手势）——`ChangeHeroineAnimationForInteger` 只改枚举不驱动播放，入口在别处（`BreakAnimationBehavior` / `_breakAnimationBehavior`）。

**已废弃**：`ChangeHeroineAnimationForTrigger` —— 同样只改枚举。

## 对架构的影响

1. 手写的整套过渡逻辑（`rampW` / `kSwitch` / `exitSmooth` / 段拼接 / 幅度预算 / 78° 硬上限）**在 native 路径上全部不需要**
2. 游戏自己会"先收尾当前动作 → 起新的 → 播完回落"，正是我们手搓那套的目标
3. 分层结构允许**只替换 L0**，表情（L2）、视线（L1）、说话（L3）不受影响
4. 手势仍需采样路径或另找 Base001 入口

# 补充验证（同夜）

## J. Base001 手势的正确入口

`ChangeHeroineAnimationForInteger` 对 Base001 只改枚举不播。真正能用的是：

```
HeroineService.ChangeAnimation(AnimationType)
```

实测 `ChangeAnimation(Base001_Motion12_Start_Nod)`：

```
+0.5s  L0 = anim_break_novel_base_end  t=0.47/3.19   ← 先收尾当前动作
+2.5s  L0 = anim_story_base001_sub_nod t=0.76/2.17   ← 再播点头
```

**和 Wild001 一样是"先收尾再起新的"。**

## K. 三个入口对照

| 入口 | Wild001 | Base001 | 结论 |
| --- | --- | --- | --- |
| `ChangeHeroineAnimationForInteger(int)` | ✅ 播 | ❌ 只改枚举 | 用于野生动作 |
| `ChangeAnimation(AnimationType)` | 待测 | ✅ 播 | 用于手势 |
| `ChangeHeroineAnimationForTrigger(AnimationType)` | ❌ | ❌ | 废弃 |

## L. Base001 的自动播放器

`HeroineNormalAnimationController._breakAnimationBehavior` 是 `BreakAnimationBehavior`：

```
UpdateAnimation()                    每帧跑
_baseAmount        = 5000
_enjoyAmount       = 0
_enjoyChangingAmount = 0.01          逐渐涨
_baseDelaySeconds  = 1 .. 2          普通节奏：每 1~2 秒换一个小动作
_enjoyDelaySeconds = 0.3 .. 0.5      "享受"节奏
_nextAnimation / _beforeChangeAnimation / _currentAnimLoopCount
```

**待机时的 Base001 小动作是它自己随机挑的**，`UpdateAnimation` 内部会重写 `_nextAnimation`。手动设 `_nextAnimation` 会被下一次选择覆盖——所以要走 `ChangeAnimation`，不要走 behavior 字段。

## M. 冲突测试：采样层 vs 原生层

操作：先让我们的采样层播 `anim_break_yawn_1`（5333ms），1.2 秒后调 `play 74`。

```
日志： play anim_break_yawn_1 (…) d=5333 on Character
状态： currentAnimationType = Wild001_Motion25_Memorie
       L0 clip = anim_break_novel_base_end
日志： 无 clip done
```

**结论**：两层会打架。

- 游戏 Animator 照常推进，`_currentAnimationType` 被改成 `Memorie`
- 但骨骼由我们 `LateUpdate` 覆盖（比 Animator 晚）
- 画面上演的是**我们的采样**，游戏以为自己在演别的
- 我们的 cue 没有收尾日志，说明状态机被搅乱

**所以两层必须互斥**：同一时刻只允许一个写 L0。

# 落地实现（同夜）

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `lib/anim-type.js` | **新增**。`NATIVE_TYPES` 映射表 + `toNative(verb)` |
| `lib/arrange.js` | 生成 cue 时 spread `toNative(n.verb)`，带上 `nativeName` / `nativeId` |
| `brain.mjs` | `buildCueItem` 与 `actCues` 两处重建对象的地方各补一行，把原生标记搬过去 |
| `game/src/PerformerPlugin.cs` | `CueDto` 加两个字段；`ParseActDict` 解析它们；`Perform` 分流到 `PlayNative`；`LateUpdate` 开头 `if (nativeBusy) return;` |

## 关键坑

**`ParseActDict` 是手写解析器。** DLL 不用 `JsonUtility` 反序列化 `ActDto`（只有 `HealthDto` 用了），而是把 JSON 转成 `Dictionary<string, object>` 再逐字段读。新加的字段**必须在 `ParseActDict` 里显式解析**，否则 brain 那边写了也白写——现象是"改了半天没反应"，日志一切正常。

`brain.mjs` 侧也有两处同样的坑：`buildCueItem` 和 `actCues` 都在**重建对象**（`map` 出新对象），新字段不显式搬过去就静默丢失。
