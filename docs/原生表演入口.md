# 游戏原生表演的完整入口

探到 `HeroineAI` 之后，整件事变了：**她"正在做什么"是游戏的一个显式状态，不是我们从骨骼姿势里反推出来的。**

## 两层状态机

### `HeroineAI.ActionStateType` —— 她在做什么（33 个值）

```
GameStartDirection=0     WantTalk=1              MainStory=2         ClickHeroine=3
WildStretchFullBody=4    WildStretchShoulder=5   WildTea=6           WildGuts=7
WildMemorie=8            WildOpenWindow=9        WildCloseWindow=10
FromPcToBook=11          FromPcToReport=12       FromBookToPc=13
FromBookToReport=14      FromReportToPc=15       FromReportToBook=16
WorkPC=17   WorkBook=18   WorkReport=19
BreakMovie=20  BreakReadBook=21  BreakListenMusic=22  BreakTeaTime=23
BreakSleep=24  BreakForward=25
LeaveChairPreparing=26   LeaveChairGoSofa=27     LeaveChairGoFar=28
GameEndTalk=29           EventNewYearCountdown=10000   None=-1
```

**17–24 是「持续状态」**，正是我们之前只能用采样硬凑的那些。

### `HeroineAI.UpdateStateType` —— 过渡到哪一步（4 个值）

```
Idle=0   WaitFinishAction=1   EndWaitFinishAction=2   Changing=3
```

`Idle` = 稳定下来了，可以安全下达下一条指令。这是**判断"能不能插话"的官方信号**，比我们拿 `clipActive` 猜准确得多。

字段也很有用：

| 字段 | 含义 |

## 实测：持续状态全部可用

用 `state <Name>` 切过去，看 L0 播什么：

| 状态 | 结果 | L0 clip | 长度 |
| --- | --- | --- | --- |
| `WorkPC` | ✅ | `anim_work_pc_base_loop` | 10.00s loop |
| `WorkBook` | ✅ | `anim_work_book_base_loop` | 10.00s loop |
| `WorkReport` | ✅ | `anim_work_report_base_start` | 3.60s |
| `BreakMovie` | ✅ | `anim_break_movie_base_loop` | 17.83s loop |
| `BreakReadBook` | ✅ | `anim_break_novel_base_loop` | 5.00s loop |
| `BreakListenMusic` | ✅ | `anim_break_music_base` | 4.00s |
| `BreakSleep` | ⚠️ 需前置 | `anim_break_sleep_base` | 6.00s |
| `BreakForward` | — | `anim_break_forward_base (1)` | 2.33s |

**`BreakSleep` 有前置条件**：直接 `DebugChangeState(24)` 会被**静默吞掉**（`GetCurrentState` 还是上一个）。必须先 `ActivateSleepFlg()`。这是游戏自己的门槛，抄下来就够了。

**`BreakForward` 不是独立状态**：切过去之后 `GetCurrentState` 返回 `BreakMovie`，L0 播 `anim_break_forward_base`——它是"看电影时快进"，依附在 `BreakMovie` 上。

**`UpdateStateType` 立刻回到 `Idle`**，但 L0 的 clip 要几帧才换（CrossFade）。所以查询"切换成功没有"要看 `anim=`，不要看 `L0=`。

## 这比逐帧采样强在哪

采样路径要自己解决三件事：循环点、归还姿势、和游戏状态机抢骨骼。持续状态用官方入口，这三件全部消失：

- **循环点**：`base_loop` 是 `isLooping=True` 的 clip，Unity 自己处理
- **归还姿势**：游戏从 `base_loop` 切到 `base_end` 再回落，全程它自己管
- **抢骨骼**：我们根本不碰骨骼

代价是**控制权交出**：切过去之后她按游戏自己的节奏演，我们只能等 `update=Idle` 再下一条。

## 命令

```
state                # 查询：state= / update= / anim= / L0=clip len= loop=
state WorkPC         # 切过去（内部调 DebugChangeState）
state BreakSleep     # 自动先 ActivateSleepFlg
```

`state` 无参时输出形如：

```
state=BreakTeaTime
update=Idle
anim=BreakBase004
L0=anim_break_tea_base_loop len=9.00 loop=True
```

## 抗更新

这套入口的抗更新性来自**不写死任何东西**：

1. **状态名不写死**：`state <Name>` 走 `Enum.Parse(ActionStateType, name, true)`，游戏改名就换个名字，代码不用动
2. **找不到状态 = 报错一行**，不是崩溃
3. **`BreakSleep` 的前置**：`ActivateSleepFlg` 找不到就跳过，`DebugChangeState` 照样发（大不了被吞）
4. **`state` 查询永远可用**：`GetCurrentState` / `_currentAnimationType` 都是公开成员，读不到就少打一行

## 表情也是原生路径

`FacialType` 只有 8 个值（实测 `enum FacialType`）：

```
None=0  Shy_Rest=1  Shy_Fun=2  Shy_Anger=3
Shy_Sad=4  Shy_Joy=5  Shy_Surprise=6  Open_Eye=18
```

`ChangeHeroineFacialAnimation(Int32)` 的参数是 **Int32 不是枚举**，得自己按 `FacialType` 换。
实测 `ChangeHeroineFacialAnimation(2)` → L2 层播 `anim_face_shy_fun`。

表情落在 **L2 Facial 层**，跟 L0 身体动作互不干扰——所以她可以一边写着代码一边害羞。

## 服务端已接

`lib/actions.js` 的 7 个持续状态 verb 加了 `state` 字段：

| verb | state | L0 clip |
| --- | --- | --- |
| `work_pc` | `WorkPC` | `anim_work_pc_base_loop` 10.00s loop |
| `work_report` | `WorkReport` | `anim_work_report_base_start` 3.60s |
| `read_book` | `WorkBook` | `anim_work_book_base_loop` 10.00s loop |
| `novel` | `BreakReadBook` | `anim_break_novel_base_loop` 5.00s loop |
| `movie` | `BreakMovie` | `anim_break_movie_base_loop` 17.83s loop |
| `music` | `BreakListenMusic` | `anim_break_music_loop_high` 2.67s loop |
| `sleep` | `BreakSleep` | `anim_break_sleep_base` 6.00s |

链路：`actions.js` 的 `state` → `toNative(verb)` 返回 `{ stateName }` → `arrange.js` spread 进 cue →
`brain.mjs` 的平行数组 `stateNames` / `facials` → DLL `CueDto` → `SwitchState()`。

**`toNative` 里 state 优先于 native**：持续状态是"她在干什么"，不是"演一下"，
有 state 就不该退回采样。


**采样归零**。之前那 3 个采样（`work_pc` / `read_book` / `thinking`）全部改成状态切换。

## 踩到的三个语义坑

**① `sleep` 的主语规则不能动**

`sleep` 原本是 `hisBody: true, companion: false`——他说"我要睡了"是他的事，她不该跟着趴。
我一度改成 `false/true` 想让她陪着睡，`director.test.mjs` 立刻挂了：

```js
test('主戏：他要睡了，不让她趴下', () => {
  const r = decideCore('我要睡一会儿了', [])
  assert.ok(!r.core || r.core.verb !== 'sleep', '不该判成她趴下')
  assert.equal(decideCore('你眯一会儿吧', []).core?.verb, 'sleep')
})
```

测试是对的。`state: 'BreakSleep'` 保留——它只在 `sleep` **被选中**时生效，
也就是"你眯一会儿吧"这种她被指到的场景。**状态字段和主语规则是两件事，不冲突。**

**② 正则写死词序会漏**

- `music.re` 原来是 `/听歌|音乐|耳机|放首歌/`——"听会儿歌"中间夹了字，匹配不到 →
  改成 `/听.{0,4}歌|…/`
- `sleep.re` 原来是 `/趴一会|趴着|眯一会|眯一下|睡一会|睡一下/`——"先睡会儿"不是"睡一会" →
  加 `睡.{0,2}觉|睡.{0,2}会儿|睡觉`

漏掉之后判定会落到 `yawn` 的 `/困/` 上，看起来像"她说困却被安排打哈欠"。

**③ 回归脚本不认 `state:` 行**

`live-performance.ps1` 只统计 `native play` / `native done` / `play anim_` 三种。
状态切换打的是 `state: A -> B`，于是走状态的场景全被判成 `nothing`。
**"没演"和"演了但日志没记"必须分清**，否则会去修一个不存在的 bug。
