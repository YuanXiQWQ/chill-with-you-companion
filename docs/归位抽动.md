# 归位抽动：量化与修复

## 症状

大动作（伸懒腰、哈欠这类）演完回到待机时，手臂"啪"一下弹回原位。

## 先把它变成数字

眼睛看不准，也容易把两件事混成一件。加了 `trace` 探针：插件在 `Update` 里每 50 ms 记一行骨骼**四元数**，写成 `BepInEx/chill-trace.txt`。

```powershell
# 写 BepInEx/chill-cmd.txt
trace 40
```

格式：

```
t|anim|native|clip|Hips|Head|LFA|RFA|LUL
165.575|BreakBase002|0|0|1.0000,0.0000,...|...
```

`native` / `clip` 两列是**关键**：能直接看出那一刻是谁在写骨骼。

> 为什么必须做进 DLL：外部命令走文件轮询，实测只有 2 Hz 上下。0.1 秒的回弹抓不到，只会看到"前后两帧差很多"而不知道中间发生了什么。

### 为什么记四元数而不是欧拉角

**第一版记的是 `localEulerAngles`，量出一堆假尖峰。**

```
t=171.588  Head=270.2,173.4,276.5
t=171.638  Head=270.8,58.2,31.6      ← 看起来 Y 转了 115°
```

我据此判断"这是 `LookPlayer` 层在转头看你"——**错的**。

换四元数、用 `2*acos(|dot(q1,q2)|)` 重算同一段，那 115° 变成不到 3°。

原因：欧拉角在 `x` 接近 ±90° 时会 gimbal 耦合，同一个微小旋转能算出 100° 以上的"跳变"。**拿欧拉角算角速度，本质上是在追幻影。**

## 第一次量到的真实结果

| t | dt | 骨 | 角度 | °/s | anim | native | clip |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 170.60 | 50ms | 左前臂 | 100.4° | 2008 | StretchFllBody | 1 | 0 |
| 175.85 | 50ms | 头 | 85.5° | 1710 | StretchFllBody | 1 | 0 |
| **178.72** | **67ms** | **右前臂** | **105.6°** | **1576** | **BreakBase002** | **0** | **0** |

前两行是伸懒腰**本身**（挥臂、抬头，就该猛），第三行才是问题：

**`native=0 clip=0`** —— 那一刻我们**全程没写骨骼**。

**结论：这个抽动不是我们写出来的，是游戏的 `CrossFade` 太快**。它用一两帧把手臂从"举着"拉回"放腿上"，105° 分两步走完。

`native done` 日志时间和切换点对齐：`177.338` 还是原生，`177.405` 已经 `BreakBase002`。**释放那一帧姿势是连续的（差 0.1°），跳的是之后两步。**

> 这三行是欧拉角算的。数值上它们和四元数结果同量级（这是真的大幅动作，不受 gimbal 影响），所以结论成立。

## 修法：释放后接管 350 ms

不改游戏的任何东西。在 `PlayNative` 放手**之前**把当前姿势拍成快照，放手后 350 ms 内每帧做：

```cs
bones[i].localRotation = Quaternion.Slerp(nativeExitRot[i], bones[i].localRotation, k);
```

`k` 从 0 走到 1。k=0 时保持快照，k=1 时就是游戏自己的姿势，之后彻底撒手。

**只接管移动量、不改终值。** 终值始终是游戏写的那个，所以不会把姿势带偏。

窗口长度是 `NativeExitBlend`，默认 `0.35f`，想更慢就调大。

## 效果（四元数真值）

释放后 0.5 秒内，逐帧：

```
t        dps  bone  deg
165.575   30  LFA    1.6
165.625  143  RFA    7.1
165.675  298  RFA   14.9
165.725  424  RFA   21.2
165.775  529  RFA   26.5   ← 单帧峰值
165.825  460  RFA   23.0
165.875  204  RFA   10.2
165.926  142  RFA    7.3
165.993   85  RFA    5.7
166.043   77  RFA    3.9
```

**钟形曲线：起步慢、中间快、收尾慢，没有任何单帧突变。**

| 版本 | 释放窗口内峰值 |
| --- | --- |
| 原版（不接管） | **1576 °/s** |
| 软着陆 0.35s | **529 °/s** |

降 66%，且形状从"两步走完"变成"一条平滑曲线"。

## 窗口外只剩一处

四元数重算后，整段 40 秒里超过 800 °/s 的**只有一处**：

```
t=160.651  RFA  48.8°  975 °/s   Wild001_Motion1_StretchFllBody
```

**在原生动作内部**——伸懒腰挥手臂，本来就该快。释放点在 165.575，这个在 5 秒前。

**归位窗口外没有任何真尖峰。**

## 探针使用说明

```powershell
pose          # 6 根骨的角度快照（欧拉角，人看用）
trace 40      # 连续记 40 秒四元数到 BepInEx/chill-trace.txt
```

`trace` 必须放在 `LateUpdate` 里 `nativeBusy` **之前**——要抓的正是 `nativeBusy` 从 true 翻回 false 那几帧，放后面就会漏掉。

## 复现步骤

```powershell
# 1. 开始记录
[IO.File]::WriteAllText("$g\chill-cmd.txt", "trace 40`n", (New-Object System.Text.UTF8Encoding($false)))
# 2. 触发大动作
POST /chill/v1/act  {"text":"伸个懒腰吧","sandbox":true}
# 3. 等 trace 结束（40 秒）
# 4. 算角速度
```

**算角速度必须走四元数**：

```powershell
function QAng($a, $b) {
  $d = [math]::Abs($a[0]*$b[0] + $a[1]*$b[1] + $a[2]*$b[2] + $a[3]*$b[3])
  if ($d -gt 1) { $d = 1 }
  return 2 * [math]::Acos($d) * 180 / [math]::PI
}
```

用欧拉角差分（带 360 环绕修正）也能跑，但会在 gimbal 附近报出 100° 以上的假尖峰。
