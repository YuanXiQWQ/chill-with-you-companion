# 离座真相：她从来没有"走过去"

> 2026-11-15 22:20–22:36 实测。结论推翻此前全部离座架构（`seat-trip` 的 clip 时间轴、
> `TripWalk` 位移、`RoomView` 切相机）。证据全部可复现，方法见 §5。

## 1. 一句话

**游戏里"她走到沙发"在坐标上不存在。** "沙发"是一个**动画状态**，不是一个空间位置。

## 3. 游戏自己的结构

```
HeroineAI  (Character/HeroineAI，挂 MyUtil.StateMachineMonobehavior<HeroineAI>)
├─ NextActionSelector        自动行为调度：WildMotionDelayMinutes=30，概率 25%
├─ LeaveChairJudge           HasLeaveChairPlan() / StartLeaveChair() / Dispose()
│   └─ LeaveChairPlan        是 enum（value__ Int32），已实测可用值：Sofa
├─ HeroineService            Animator / Transform / 相机 / RoomPlace
├─ HeroineUseObjectController 杯子、笔、书、咖啡机（她"用物件"的挂点）
└─ HeroineStateXxx ×30       每个状态一个组件，各自跑 Enter/Update/Phase
```

离座 = 三个状态 + 一次判断：

```
LeaveChairJudge.HasLeaveChairPlan()
  → HeroineStateLeaveChairPreparing
  → HeroineStateLeaveChairGoSofa  |  HeroineStateLeaveChairGoFar
  → OnLeaveChairFinished() → SetHeroineAwayStatus / SetHeroineSeatedStatus
```

`GoFar` 是"去远处拿吃的/冷饮"：`Phase` + `_startSeconds` + `_stayMaxSeconds` +
`_soundPlayAtSeconds` + `_takeSnackType`（HeroineSnackType）+ `_isTakeColdDrink`。
回来用哪段 also 取决于拿了什么：`Sofa / Normal / Cup / Cookie / Cupcake / BreadA / BreadB`。

## 4. 沙发上"待着"是权重 + 秒表的轮转器

`HeroineStateLeaveChairGoSofa` 的字段（实测值）：

| 行为 | Delay | Invalid（冷却） | 权重变化 |
| --- | --- | --- | --- |
| thinking（发呆） | 40–70s | 180s | 0.02 |
| lookOutside（看窗外） | 40–70s | 180s | 0.02 |
| controlHeadphone（摸耳机） | 15–20s | 10s | 0.01 |
| base（回到 sofa_loop） | 5–10s | —— | —— |

`_initBaseAmount = 10000`，四个 `_xxxAmount` 当权重，三个 `MyStopWatch` 记冷却。
**每 5~70 秒重抽一次"下一步干什么"**，每种演 `start → loop → end` 后回到 `sofa_loop`。

所以它不是"按住一条 loop 三分钟"——那会看着像定格。它是十几段小动作在轮转。

## 7. 还没解决

- `_currentPlace` 始终是 `Desk`。如果游戏正式路径（不是 Debug 入口）会调
  `ChangeHeroineTransform`，那我们的入口就少了这一步——但没有证据表明它会被调用
  （`_heroineTransform` 是空表）。**看屏幕确认一次即可**：她演沙发时画面里是沙发还是书桌。
- `cam=MainCamera` 是观测盲点（`ChangeCameraTransform` 改的是 transform，名字不变）。
  要判断相机到底动没动，得把 `WatchTick` 改成记 `Camera.main.transform.position`。

## 8. 演出期间让游戏闭嘴（`GameVoiceGate`）

我们的字幕/语音在播的时候，游戏自己的"自言自语"（弹幕）和她自己的语音会一起出来，
两套台词打架。两个开关实测都能在运行时改：

| 对象 | 成员 | 默认 |
| --- | --- | --- |
| `HeroineSelfTalkController`（挂 HeroineAI） | `_selfTalkProbability` int | 75 |
| `HeroineAI._heroineVoiceController` | `CancelVoice()` | —— |
| 同上 | `ChangeEnableHeroineTalkAnimation(bool)` | true |

`GameVoiceGate`（`PerformerPlugin.cs` 内嵌类）在 `queue: play` 之前 `Enter`、条目演完 `Exit`：
进入时把概率存下来改 0 + `CancelVoice()` + 关口型，退出时写回原值 + 开口型。

- `depth` 计数：连续条目不会来回抖。
- 超时兜底：`expireAt` 到点但 `depth==0` 就强制恢复——协程被 `StopCoroutine` 停掉时没人调 `Exit`，
  没有这道兜底她会永久失声。
- 日志：`voice gate: 演出开始…` / `voice gate: 恢复游戏语音…`，一眼可查。

实测（22:39）：

```
voice gate: 演出开始，游戏自言自语/语音已关（queue seq=1794753206）
queue: play seq=1794753206 depth=0 waited=0.2s cues=1 sub=你要看书的话，正好，我也停手。
voice gate: 恢复游戏语音（演出结束）
```

恢复后 dump 回读 `_selfTalkProbability = 75`，原值没丢。

### 8.1 离座那句语音是游戏的，要抢在它前面关

游戏离座走的是 `PlayLeaveChairVoiceThenGo` —— **先播它自己的语音，再起身**。
所以 gate 必须在 `DebugForceLeaveChair` **之前**关上，晚了就抢不过：

```csharp
GameVoiceGate.Enter("trip " + planName, holdSec);   // 先关闸
mi.Invoke(ai, new object[] { plan });               // 再让它动
```

而且 `CancelVoice()` 只打断"这一刻正在响的"，游戏完全可能在我们之后才起播。
所以 `Tick()` 在压住期间**每 0.5 秒再打断一次**（`nextCancelAt` 节流）：

```csharp
if (Time.unscaledTime >= nextCancelAt) { nextCancelAt = Time.unscaledTime + 0.5f; Invoke0(voice, "CancelVoice", null); }
if (Time.unscaledTime < expireAt) return;
Restore("到点恢复");
```

**没管的**：剧情语音（`game busy=true (hard story-voice:…)`）是主线的，不属于"她的自言自语"，
打断它会破坏剧情，所以保留。若以后要连它也压，只能在 BepInEx 自带的 HarmonyX 上
patch `HeroineVoiceController.PlayVoice`，那是另一档风险，得单独评估。

### 8.2 不许连点：`TripGuard`

`DebugForceLeaveChair` **不能连点**。2026-11-15 22:47 的事故现场：

```
22:47:01  trip 启动（awayMs=205271）
22:48:29  trip 又启动 → 游戏收到第二个指令，直接播 comeback（没走完就回）
          # 想用 OnLeaveChairFinished() 收尾，结果 base → go → loop 死循环
```

原因是 `DebugForceLeaveChair` 绕过了 `LeaveChairJudge` 的正常复位，
`HasLeaveChairPlan()` 一直为真，她一回来就立刻又走。收场只能重启游戏。

`TripGuard` 就是拦这个：

| 规则 | 值 | 说明 |
| --- | --- | --- |
| 离座动画在播就不许再触发 | `WatchTick` 每 0.4s 采样 `leavechair` | 喂 `lastSeenAt` |
| 多久算这一趟结束 | 12 秒没看到离座动画 | 太短会在 `go` 之前误清 |
| 硬上限 | 480 秒 | 状态机真卡死时，也不能让她永远不能离座 |

实测（22:58，故意绕过侧车的 `state.away` 锁来测游戏端这一层）：

```
trip: 已交给游戏自己的状态机 DebugForceLeaveChair(Sofa)     ← 第一次
watch: clip=anim_wild_leavechair_sofa_go
watch: clip=anim_wild_leavechair_sofa_loop
trip: 忽略 Sofa —— 她还在离座中（离座动画 0s 前还在播）       ← 第二次被拦
```

于是变成两层：**侧车 `state.away`（业务锁）→ 游戏端 `TripGuard`（物理锁）**。
侧车那层管"不该在这时候让她走"，游戏端这层管"她已经在走了，指令进不来"。

## 9. 定案：先播我们的，再接离座

2026-11-15 23:18 定案。游戏的离座语音/字幕不碰（Debug 入口本来也不播，实测零语音源），
只要时序对：

```
她在看书                               anim_break_novel_base_loop   ← 空闲，可以走
queue: play cues=0  sub=这个点了。沙发那边要拿条毯子吗？
                                       ← 我们的字幕 + 我们的语音，3.7 秒
queue: play cues=1  sub=-              ← trip 条目
trip: 已交给游戏自己的状态机 DebugForceLeaveChair(Sofa)
                                       anim_break_novel_base_end    ← 合上书
                                       anim_story_base001_base      ← 起身
                                       anim_wild_leavechair_sofa_go ← 走向沙发
```

两条 clip 的分工：`brain.mjs` 一次 act 产出**两条**条目——先说，再走。
第二条等到第一条的语音播完才起（`queue: play` 的 `waited` 就是语音时长）。

### 9.1 必须等她闲下来

23:13:56 那次没走成：她在泡茶（`anim_break_tea_sub_maker_*`），
`DebugForceLeaveChair` 调了，游戏正忙子动作，**直接把调用吞了**——`trip.log` 记了 start，
画面里却没动。

所以 trip 请求是**挂起**的：

```csharp
TriggerLeaveChair(plan, holdMs)   // 只登记
  → TryFlushTrip()                // Update 每帧试
      → IsGameIdle() ? FireLeaveChair : 继续等（30 秒超时丢弃）
```

`IsGameIdle()` 只看动画名：`_base` / `_base_loop` / `_idle` / `anim_story_base*` 算闲；
`_sub_*`（泡茶、翻页、喝东西）和 `leavechair` 一律算忙。

### 9.2 TripGuard 的判据必须看当下

上一版靠 `WatchTick` 喂 `Seen()` 记"最后一次看到离座动画的时间"，结果误判：
她明明在 `novel_base_loop`，日志却报「离座动画 0s 前还在播」，把正常的一趟挡掉了。

根因是两处 `TryBegin` 重复调用（`TriggerLeaveChair` 和改名后的 `FireLeaveChair` 各留了一行），
第二次看到自己刚设的标志，就以为在离座。

现在 `TripGuard.TryBegin()` 只做一件事：**读这一帧的 `Animator.GetCurrentAnimatorClipInfo(0)`，
名字里有 `leavechair` 就拒绝**。不存历史状态，也就不会误判。
