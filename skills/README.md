# 随插件分发的技能

这两个技能文档描述的都是 **dsh-chill-with-you-companion 插件自身的行为**，不是某台机器的目录布局。它们随插件一起发布，装完插件就有。

| 技能 | 什么时候用 |
| --- | --- |
| `chill-with-you-testing` | 要给 `/chill/v1/act`、`/chill/v1/play` 写联调脚本；发现她的对话里冒出没说过的话；要清理 `cue.log` 或 `turns.jsonl` |
| `kb-authoring` | 要给她建知识库、往里加资料、核对事实来源、排查「查到了却答不出」 |

## 为什么值得读

`chill-with-you-testing` 里写的是两个真实事故：一句测试输入混进长期记忆，之后她会把那句当共同经历引用；98 条演出日志里 78 条是测试，真实演出被埋到翻不出来。

这两个事故的共同原因是**测试和真实演出走同一个接口**。文档里的三道闸门就是为了堵它——其中第二道曾经写成 `act.sandbox`，闸门静默失效，一周都没人发现。这类错不会报错，只会让隔离看起来做了其实没做。

`kb-authoring` 的核心是「查到了却答不出」的六类坑。知识库做出来检索命中率很高、回答却不用资料，原因基本都在这六类里——最常见的是历史污染：她连着三次说「不知道」，这件事就变成了她的既有立场，再怎么改库都没用。

## 装法

如果 DSH 读的是 `<DSH_HOME>/skills/`，把两个目录拷过去：

```bash
cp -r skills/chill-with-you-testing skills/kb-authoring <DSH_HOME>/skills/
```

插件自带的 `skills/` 目录如果被支持，也可以直接在配置里指过来，不必复制。

## 写法约定

两份文档都遵循同一套：

- **路径相对插件根目录**，不写盘符。`data/memory/turns.jsonl` 就是插件根下的相对路径。
- **命令用 `curl` / `node`**，PowerShell 单独放附录。插件本身只跑在 Windows 上，但读文档的人未必用 PowerShell，混着写会让示例没法照抄。
- **端口写了默认值**（侧车 `10723`、面板 `10722`）并注明可改。改过端口的话，所有命令和 `isAutomation` 里的 `panelPort` 要一起换。

## 改这两个文档时注意

技能的 `description` 决定它会不会被自动加载。改动时保留这些触发词，否则该用的时候不会触发：

- `sandbox`、`cue.log`、`turns.jsonl`、`/chill/v1/act`、`/chill/v1/play`、测试污染
- 知识库、来源分级、检索命中差、回答不用资料
